# 网关压测机器人

机器人先通过 HTTP API 注册独立账号、登录、查询角色并创建角色。准备完成后才开始计时；各机器人按指定的爬坡时间领取一次性票据、建立 TCP 连接并认证，然后发送 Echo 和心跳。领取票据之前，如果访问令牌已经过期或剩余有效期不超过 30 秒，机器人会通过刷新令牌接口轮换一次，避免大批量准备使较早账号的令牌过期。每个机器人只有一个连接和一个在途请求，不自动重连，不重试失败请求。

每 10 次请求中有一次心跳，其余为 Echo。机器人检查响应类型、请求序号、角色 ID、Echo 原始消息体和心跳服务器时间。延迟从写入请求之前计时，到完整读取并校验响应之后结束。

## 本地运行

服务启动后，在项目根目录执行：

```bash
go run ./cmd/robot -bots 50 -duration 30s -ramp 5s -rate 2 -report robot-report.json
```

Docker Compose 使用服务名称访问登录服务和网关：

```bash
docker compose --profile tools run --rm robot \
  -bots 50 -duration 30s -ramp 5s -rate 2 \
  -report /reports/run.json
```

`ROBOT_LOGIN_URL`、`ROBOT_GATEWAY` 和 `ROBOT_SERVER_ID` 作为命令行参数的默认值；命令行同名参数优先。Compose 已提供容器网络地址。直接运行默认访问 `http://127.0.0.1:8080` 和 `127.0.0.1:9000`。传入 `-gateway ''` 时使用票据接口返回的网关地址。

逐步增加压力，例如：

```bash
go run ./cmd/robot \
  -login-url http://127.0.0.1:8080 -gateway 127.0.0.1:9000 \
  -bots 1000 -duration 120s -ramp 30s -rate 5 \
  -payload-bytes 256 -prepare-concurrency 4 \
  -report robot-1000.json
```

1000 个机器人会创建 1000 个账号和角色；每次运行使用随机账号前缀，数据保留在数据库中。`-prefix` 可以设置新的唯一前缀，重复使用同一前缀会因账号已存在而失败。凭据只存在机器人内存中，不写报告；该版本不复用历史账号。

## 参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `-bots` | `50` | 目标连接数，每个连接对应独立账号和角色 |
| `-duration` | `30s` | 网关阶段总时长，包含爬坡时间，不包含账号准备 |
| `-ramp` | `5s` | 均匀分散连接开始时间；必须小于总时长，最大 10 分钟 |
| `-rate` | `2` | 每个机器人的目标消息频率，范围 0.001 至 1000，包含 Echo 与心跳 |
| `-payload-bytes` | `128` | Echo `data` 字符串长度，JSON 包装另外占 11 字节 |
| `-prepare-concurrency` | `4` | 账号准备并发数，范围 1 至 64 |
| `-timeout` | `5s` | 每次 HTTP 操作或 TCP 往返的超时 |
| `-server-id` | `s1` | 登录和角色所属游戏服务器 |
| `-prefix` | 随机 | 新账号前缀，仅小写字母、数字和下划线，最多 20 字符 |
| `-report` | `robot-report.json` | 完整 JSON 报告；空字符串表示仅写标准输出 |
| `-tls` | `false` | 对自定义 TCP 协议启用 TLS 1.3 |
| `-tls-ca` | 空 | 额外信任的 PEM CA 文件，不替换系统根证书 |
| `-tls-server-name` | 空 | 证书验证使用的域名；默认为连接地址中的主机名 |

自定义 TCP 协议启用原生 TLS 的示例：

```bash
go run ./cmd/robot \
  -login-url https://login.example.com \
  -gateway gateway.example.com:9000 -tls \
  -tls-ca ./certs/ca.pem -report robot-tls.json
```

不提供跳过证书验证的选项。HTTP 登录地址的 HTTPS 使用系统信任根；`-tls-ca` 只作用于 TCP 网关。

## 报告与结果判定

运行期间每 5 秒向标准错误输出阶段进度，结束时将完整 JSON 输出到标准输出和 `-report` 文件。报告不包含密码、访问令牌、刷新令牌或一次性票据。错误样本最多保留 20 条。

报告包括账号准备耗时、网关实际运行时长、令牌刷新结果、TCP 连接和认证结果、峰值在线数、消息成功和失败数、超时数、实际 TCP 读写字节数，以及连接、认证、消息往返的平均值和 P50/P95/P99/最大延迟。延迟采用固定大小的 256 桶直方图，分位数向上取桶边界，精度约为 10% 或 1 微秒；不会为每条消息存储样本。字节数包含协议头和认证帧，启用 TLS 时统计的是加密之前的协议流量。

`achieved_messages_per_second` 为成功消息数除以网关阶段实际经过时间，包含爬坡和认证。`message_error_rate` 为失败消息数除以成功与失败消息总数；连接、票据或认证错误有单独计数，不能仅凭消息错误率判断成功。`messages_canceled_at_end` 是到达运行时限或接收中断信号时未完成的在途请求，不计为网关错误。

所有请求账号准备成功、所有目标机器人认证成功、至少一条消息成功、且没有连接/认证/票据/消息错误时，`passed=true`，进程退出码为 0。参数错误退出码为 2，压测失败或被中断退出码为 1。`Ctrl+C` 会关闭连接并尽量保存报告。

## 容量测试建议

账号准备需要执行真实密码哈希，可能明显慢于建立 TCP 连接。准备阶段单独计时，但登录限流仍然有效。较大压测可在隔离测试环境中调高 `AUTH_RATE_LIMIT`，并检查 `BCRYPT_CONCURRENCY`、`GATEWAY_MAX_CONNECTIONS`、消息速率上限和操作系统文件描述符限制。准备并发数应不高于登录服务的密码哈希并发上限，否则服务会返回 503；机器人会将其作为真实失败记录。服务端环境变量的确切名称见主 README 和 `.env.example`。

先确认 50 个连接的链路正确，再按 100、500、1000 等阶梯增加，记录服务端 CPU、内存、文件描述符、网络、Redis 延迟和 P99。建议将机器人和服务端部署到不同主机；同机测试会竞争 CPU，不能直接当作生产容量。当前机器人采用固定频率、单在途请求的闭环模型，服务变慢时实测发送频率会下降；适合连接和基本协议吞吐测试，不能替代真实游戏业务、突发流量、长时间稳定性及开放到达率测试。
