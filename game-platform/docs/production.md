# 上线前的工程工作

这套代码提供可运行的工程基础，包括认证、角色、一次性票据、TCP 网关、共享会话状态和压测工具。“企业级”还取决于部署环境、业务一致性、容量验证、运营流程及故障恢复，本项目不把本地可运行等同于已经具备生产服务等级保证。

## 接入安全

- 在公网入口为登录 API 启用 HTTPS，为 TCP 网关配置 TLS 终止或启用原生 TLS 1.3（`GATEWAY_TLS_CERT` 与 `GATEWAY_TLS_KEY`）。默认裸 TCP 连接中票据和消息没有传输加密。
- 使用密钥管理服务注入随机签名密钥和数据库凭据；不要把 `.env`、密码、Access Token、Refresh Token 或入场票据提交到版本库。制定 JWT 密钥轮换方案，当前单密钥配置轮换会使旧签名失效。
- 管理端口和依赖服务只开放给可信网络。不要将 Redis、PostgreSQL 或 `/metrics` 直接暴露到公网。
- 按产品需要增加账号验证、找回密码、多因素认证、封禁、风控、第三方平台登录与未成年人合规流程。
- HTTP 限流使用连接来源地址。部署反向代理后，应在可信代理层限流，或实现明确的可信代理名单；不能直接信任任意客户端发送的 `X-Forwarded-For`。
- 网关内的连接数与单连接限流保护进程资源；公网还需要在负载均衡与网络边界处理连接洪泛和 DDoS。

## 数据与状态

- PostgreSQL 配置最小权限账号、备份、恢复演练、连接池和故障切换。迁移作为独立发布步骤执行，并在升级前验证兼容性。
- Redis 配置认证、访问隔离、容量与高可用。会话和一次性票据是临时状态；故障或数据丢失可能要求玩家重新登录。不要以绕过 Redis 校验作为故障降级方式。
- 如果游戏逻辑要严格阻止同一账号的旧连接写入，应把租约世代或栅栏令牌传递到权威逻辑服务并校验；仅靠网关 Redis 租约不能消除所有网络分区和进程暂停场景。
- 角色名与账号唯一性由数据库约束兜底。金币、道具、交易和角色删除等未来业务应另外设计事务、幂等和审计。

## 容量与可观测性

- 在与目标部署接近的网络和硬件上执行压测，分开测登录、建号、短连接风暴、长连接保活与持续发包。
- 同时观察网关 CPU、内存、GC、文件描述符、TCP 重传、网卡吞吐、Redis 延迟与连接数。机器人所在机器也可能先达到瓶颈。
- 建立连接数、认证失败、消息吞吐、错误率、延迟分位数和依赖可用性的仪表盘及告警。报告应保留版本、配置、机器规格和持续时间。
- 进程监控端点用于存活、就绪及 Prometheus 抓取；探针不代替外部端到端探测，也不能证明真实游戏逻辑可用。
- 配置容器资源上限和文件描述符，逐步增加并发，验证限流、过载与慢客户端行为。单机本地压测结果不能直接推导线上最大承载人数。
- Compose 默认 `GATEWAY_NOFILE=16384`。调整前先检查 Docker 宿主机与守护进程的文件描述符硬限制；容器不能申请超过宿主允许范围的值。

## 发布与故障演练

- 使用受控镜像仓库、依赖审计和可追溯构建；持续集成执行单元测试、集成测试、竞态检查和构建。
- 发布前验证迁移、旧新版本兼容、回滚及退出流程。关闭网关会断开其在线连接，客户端需要退避重连并申请新票据；当前没有跨实例迁移连接能力。
- 演练 Redis 不可用、数据库不可用、网关异常退出、客户端断网和慢消费者。确认服务拒绝新入场、旧连接退出与租约回收符合产品预期。
- 若要求无感重连、跨区服切换或多设备同时在线，应先调整会话与在线策略，补充消息重放、确认和去重协议，再接入真实游戏业务。
